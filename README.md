# Tom Riddle's Diary

iPad 端手写式 AI 对话日记本（汤姆里德尔日记本）。用户用 Apple Pencil 手写文字，一个「会回应的日记之魂」用**文字**回应，且这些文字必须以**逐笔生长的手绘笔触**写出来，像有人正在纸上写字。

> 私有项目。开发规则见 [`AGENTS.md`](./AGENTS.md)，当前状态与决策见 [`MEMORY.md`](./MEMORY.md)。项目名与占位 bundle ID 是内部代号，分发前必须换成原创品牌。

## 核心分工

- **Oracle（AI 层）决定「说什么」**：读识别出的文字与字迹指标，返回文字回应。
- **Handwriting 层决定「写哪些笔画」**：把文字查成字形笔画中线，排版到页面坐标。
- **StrokeEngine（本地）决定「像不像手写的」**：压感、收笔、加减速、笔间停顿、抖动、逐笔重播。

铁律：不指望模型直接输出稳定自然的最终笔画。模型只给字符；字符变笔画是本地查表与排版的结果。

最终体验是「翻开 → 手写 → 放下笔 → 收到逐笔写出的回应」。用户只应看到回应本身，看不到任何实验室控件。

## 运行与验证

打开 `TomRiddlesDiary.xcodeproj`，scheme 选 `TomRiddlesDiary`，选一个 iPad Simulator 后 Run。

当前跑起来能看到什么：一张空白的暖米白纸。用鼠标（模拟器）或 Apple Pencil 写几个字，
停笔一会儿后左上角会渗出一点墨——那是成页预告，此刻再写一笔就能取消。不写就会成页，
DEBUG 读数（左下角）会显示笔数、停顿、算出来的成页阈值、当前阶段和识别结果。
**成页之后不会有回应**，页面会如实说明魂（Oracle）还没接入。

真正的逐笔生长和落笔中断在 Xcode 预览里看：打开 `DiaryPageView.swift`，
选预览「真笔画逐笔生长 + 落笔中断（E1 + E3d）」，进去就会逐笔写字，
你在纸上写一笔它就停在当时那一笔的半截上。

最低系统是 iPadOS 27，所以**构建必须用 Xcode 27**。命令行下用 `DEVELOPER_DIR` 指定，不必改全局 `xcode-select`：

```bash
export DEVELOPER_DIR=/Applications/Xcode-beta.app/Contents/Developer

# 测试（必须关闭并行：并行 clone 会触发工具自身崩溃）
xcodebuild -project TomRiddlesDiary.xcodeproj -scheme TomRiddlesDiary \
  -configuration Debug -sdk iphonesimulator \
  -destination 'platform=iOS Simulator,id=<iPad Simulator UUID>' \
  CODE_SIGNING_ALLOWED=NO -parallel-testing-enabled NO test

# 构建
xcodebuild -project TomRiddlesDiary.xcodeproj -scheme TomRiddlesDiary \
  -configuration Debug -sdk iphonesimulator \
  -destination 'generic/platform=iOS Simulator' CODE_SIGNING_ALLOWED=NO build

# 提交门禁
bash scripts/ip_firewall_check.sh
```

预期 `264 tests, 0 failures`（在 iPadOS 26 的模拟器上会有 4 条识别用例如实跳过） 与 `** BUILD SUCCEEDED **`。构建有一条非阻塞提示（未依赖 AppIntents，跳过其 metadata），属预期。门禁会报若干占位品牌名的 ⚠，在白名单内，属预期。

Simulator 能跑不等于体验通过：压感、书写节奏与手写识别准确率都必须 iPad 真机 + Apple Pencil 主观评审。

## 计划

计划字母是**名字，不是顺序**。执行顺序见下方单独一节。

### A 笔触修复计划

| 编号 | 内容 |
|---|---|
| A1 | ✅ 2026-08-29。抖动改成**沿弧长的连续摆动**（value noise + smoothstep），位移打在笔画法线方向。波长不是拍的：由生理性手抖频率 10 Hz 与书写速度推出（速度 ÷ 2 ÷ 频率 = 0.375 字高）。幅度顺势从 0.018 提到 0.03 字高——原值之所以那么小，就是因为白噪声难看只能压着。首尾控制值为 0，端点不动这条规则自然成立。`StrokeWobbleTests` 用「相邻偏移的平均变化量」把「不是白噪声」变成可断言的量 |
| A2 | ✅ 2026-08-29。压感改成沿弧长的连续起伏（复用 A1 的平滑噪声，波长由「力度变化频率 2.5 Hz」与书写速度推出，比手抖慢一个量级）+ 转折处加重（急转时笔尖停留久、墨渗得多，`curvaturePressureGain = 0.2`）。曲率在**摆动之前**的点上量：字形本身的转弯，不是手抖出来的弯。刻意没调 `pressureVariation`——它没有「被白噪声压小」的记录，改它就是乱调 |
| A3 | ✅ 2026-08-29。用**最小急动度轨迹**（Flash & Hogan 1985 的人类点到点运动模型）`10t³−15t⁴+6t⁵`，两端速度与加速度都为零，正好是「从静止起笔、停在静止」。**零参数**——不必回答「为什么是这条缓动曲线」，答案是「人就是这么动的」。缓动加在时间轴那一侧，`StrokeGrowth` 不用改 |
| A4 | ✅ 2026-08-29。`TimedStroke.pauseBefore`，时长由**抬笔跳跃距离 ÷ 空中速度 + 固定的抬落笔耗时**推出，不是拍一个固定秒数——同一个字里挨着的两笔间隔短，跨到下一个字的跳跃间隔长，固定秒数两头都不对。随机浮动复用 `durationVariation`，不为此再加参数 |
| A5 | ✅ 2026-08-29。把 `StrokeSample` 的压感拆成 `pressure`（按得多重，映射线宽 60%…100%）与 `contact`（笔尖有多少落在纸上，起收笔为 0，直接乘在线宽上）。两者之前揉成一个数，而压感那 60% 的下限本身是对的（手写时线不会细成头发），所以渐细永远收不到零。分开之后各自范围都保持正确，**零新增参数** |
| A6 | 修抖动在端点的统计突变（端点不动、相邻点满额噪声，形成小折角） |
| A7 | ✅ 2026-08-29。直径按 `√进度` 长（墨量随时间线性增加、面积∝直径²，所以直径∝√时间），观感是「先猛地洇开再慢慢定住」。零参数。顺带把「这一笔是点还是线」的判断从渲染层移进引擎（`PartialStroke` 改成两个 case 的枚举）|
| A8 | ✅ 2026-08-29。改成把总长**等分成整数份**。老写法在总长刚好只比上一个点多一点时，末尾会留一段长度接近 0 的碎段——摆动要在那里算法线（方向退化）、渐细要在那里判位置、渲染要画一段看不见的线，全都不报错。等分后实际间距与请求值略有出入，这是对的：间距是「大约多密」的目标，端点精确与无退化段才不能让步 |
| A9 | ✅ 刷新率跟随屏幕，不锁死 60（2026-08-26 完成） |
| A10 | ⚙️ 2026-08-30 **量尺已就位**（`Sources/Calibration/`）：成页时自动把这一轮笔迹量成数字打进控制台，并列出「量出来的 vs 现在用的 + 偏几倍」。能量的：手抖频率、抬落笔固定耗时、空中速度倍数（三者不需要知道字有多大）、书写速度与手抖幅度（需要字高估算）。**永远量不了的**：压感起伏与转折加成（这支笔没有压感）。差的只是真机上写几页字 |

### 关于手写识别的模拟器限制

**结论：PencilKit 手写识别官方支持中文，但中文识别只能在真机上验证，模拟器不行。**

实测与证据链（2026-08-27，iOS 27.0 beta 6 模拟器）：

1. `PKStrokeRecognizer.supportedLanguages` 只返回 20 种，全是拉丁字母文字：`cs, da, de, en, es, fi, fr, hi-Latn, id, it, ms, nb, nl, nn, no, pl, pt, ro, sv, tr`（`recognitionVersion = 9`）。显式 `PKStrokeRecognizer(preferredLanguages: ["zh-Hans"])` 的 `languages` 返回空数组。
2. 把模拟器系统语言改成 `zh-Hans-CN`、装上中文手写键盘并重启，结果不变。
3. 但运行时内部的 `CoreHandwriting.framework` 里，中文的码表 `ctc_zh.codemap` **在**（日韩阿俄泰越天城文的码表也都在），而**只有拉丁字母有本地模型权重** `ctc_latn.bundle`。
4. 非拉丁文字的手写模型是按需下载的系统资产（`com.apple.MobileAsset.UAF.Handwriting.*`），模拟器运行时不带。

所以这是**运行环境缺模型**，不是平台不支持。官方 session 的支持语言列表包含中文简繁与粤语。

对开发的影响：

- 拉丁字母的识别**现在就能在模拟器里测**，可以先把画布与识别的接线做完、跑通。
- 中文识别的可用性与准确率**必须等真机**（iPad 装 iPadOS 27）。在那之前不得声称中文识别已验证。
- 代码必须处理「当前设备没有某语言模型」这一真实情况：按 AGENTS.md 不静默兜底，要如实告知而不是假装识别成功。

备选路线（万一真机上中文准确率不够）：Vision 的 `RecognizeTextRequest`，`.accurate` 实测支持 `zh`、`zh-TW`、`yue`、`yue-CN` 共 30 种语言（`.fast` 只有 6 种拉丁语）。做法是把 `PKDrawing` 渲染成图再识别。代价是丢掉笔画顺序信息，而且 Vision 面向印刷体与照片文字。

顺带查到：`PKDrawing.erasePath` / `erasingPath` 是 iOS 27 新增，对「魂的笔画可被橡皮擦掉」（决策 18）有帮助。

### 手写体字体选型（E8，已废弃，留作记录）
这一节记录的是 E8 阶段的字体调研，**字体已于 2026-09-01 随 H9 从仓库删除**，现在魂的字全部由字形笔顺数据画出（E1），不再用任何打包字体。留这几行只为两件事：
一、**iOS 内置字体里没有任何中文楷体或手写体**（实测 iOS 27 运行时只有 `PingFangUI.ttc`；macOS 上那些手札体、翩翩体、楷体在 iOS 上都没有）。所以哪天真要用字体，必须自带。
二、当时用的是**寒蝉手拙体 v2.500**，作者 README 写明「免费授权全社会使用（包括商用）」并请求标注作者为寒蝉字型；那是作者的声明式授权，不是标准授权文件。当时另一个首选是**霞鹜文楷 GB**（SIL OFL 1.1，字形与笔顺遵循大陆国家标准）。要复原字体路径就从 Git 历史里翻，别照着这几行重新拍板。
